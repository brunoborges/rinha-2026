# JEP 537: Vector API (Eleventh Incubator) — JDK 27 Early Access

> Source: [openjdk.org/jeps/537](https://openjdk.org/jeps/537)
> API Javadoc (JDK 27 EA): [`jdk.incubator.vector`](https://download.java.net/java/early_access/jdk27/docs/api/jdk.incubator.vector/jdk/incubator/vector/package-summary.html)

This document summarizes the Vector API as it ships in the JDK 27 Early Access
build used by this project (`openjdk-27-ea+24`). It is a reference for the
upcoming vector-based fraud-detection implementation.

---

## 1. Summary

The Vector API lets you express **vector computations** that reliably compile at
run time to optimal SIMD (Single Instruction, Multiple Data) vector instructions
on supported CPUs, achieving performance superior to equivalent scalar code.

In JDK 27 it remains an **[incubating API](https://openjdk.org/jeps/11)** in the
module `jdk.incubator.vector`. It is **re-incubated without API changes**; the
only notable change is that the bundled **[SLEEF](https://sleef.org/)** math
library (used for ARM and RISC-V vector math intrinsics) was upgraded from
**3.6.1 to 3.9.0**.

## 2. Why use it?

HotSpot already has an **auto-vectorizer** that turns scalar loops into SIMD
instructions, but it is:

- **Limited** — only a subset of scalar code shapes are transformable, and only
  a subset of available vector instructions get used.
- **Fragile** — small changes in code shape can silently disable vectorization,
  so reliable performance requires intimate knowledge of the auto-vectorizer.

The Vector API instead lets you **write the vector algorithm explicitly in
Java**, with a programming model that makes vectorization **predictable and
robust**. This benefits domains such as machine learning, linear algebra,
cryptography, finance, and JDK internals (e.g. `Arrays::hashCode`, lexicographic
array comparison).

> For this project, the fraud detector vectorizes the 14-dimension transaction
> vector and the vector-search distance computations — a natural fit for the API.

## 3. Core concepts

### `Vector<E>`

A vector is represented by the abstract class
[`Vector<E>`](https://download.java.net/java/early_access/jdk27/docs/api/jdk.incubator.vector/jdk/incubator/vector/Vector.html).
`E` is the **boxed** element type (`Integer`, `Float`, …). A vector holds a fixed
sequence of scalar values, one per hardware **lane**.

### Element types

Six supported element types, matching the primitive numeric types:

| Boxed `E` | Primitive | Type-specific subclass |
|-----------|-----------|------------------------|
| `Byte`    | `byte`    | `ByteVector`   |
| `Short`   | `short`   | `ShortVector`  |
| `Integer` | `int`     | `IntVector`    |
| `Long`    | `long`    | `LongVector`   |
| `Float`   | `float`   | `FloatVector`  |
| `Double`  | `double`  | `DoubleVector` |

### Shape

A vector's **shape** is its size in bits and governs how it maps to a hardware
vector register. Supported shapes:

- **64, 128, 256, 512 bits**, plus **`max`**.
- A 512-bit shape packs 64 `byte`s **or** 16 `int`s, so one vector operation
  processes 64 `byte`s / 16 `int`s at a time.
- The **`max`** shape uses the maximum vector size of the current CPU. This
  enables ARM **SVE**, where sizes range from 128 to 2048 bits in 128-bit steps.

### Species — `VectorSpecies<E>`

The combination of **element type + shape** is a vector's **species**,
represented by
[`VectorSpecies<E>`](https://download.java.net/java/early_access/jdk27/docs/api/jdk.incubator.vector/jdk/incubator/vector/VectorSpecies.html).

> **`number of lanes = vector size (bits) / element size (bits)`**

Use `XxxVector.SPECIES_PREFERRED` to get the species whose shape is optimal for
the current CPU, and store it in a `static final` field so C2 treats it as a
compile-time constant.

## 4. Operations

Operations are either **lane-wise** or **cross-lane**:

- **Lane-wise** — applies a scalar operator (e.g. add) to each lane in parallel,
  usually producing a same-length, same-shape vector. Sub-classified as
  *unary*, *binary*, *ternary*, *test*, and *conversion*.
- **Cross-lane** — applies across the whole vector, producing a scalar or a
  vector of a possibly different shape. Sub-classified as *permutation* and
  *reduction* (e.g. summing all lanes to a scalar).

To keep the API small, generic methods accept an **operator constant** of type
[`VectorOperators.Operator`](https://download.java.net/java/early_access/jdk27/docs/api/jdk.incubator.vector/jdk/incubator/vector/VectorOperators.Operator.html)
(constants live in
[`VectorOperators`](https://download.java.net/java/early_access/jdk27/docs/api/jdk.incubator.vector/jdk/incubator/vector/VectorOperators.html)).
Convenience methods (`add`, `mul`, …) exist for common *full-service* operations.

> **Shape-changing vs shape-invariant** — conversion/reinterpretation operations
> can change shape, hurting portability and performance. Prefer the
> **shape-invariant** flavor of each operation and write shape-invariant code.

Type-specific subclasses (e.g. `IntVector`, `FloatVector`) add operations bound
to the element type: reductions, array load/store, integral bitwise ops, and
floating-point transcendental functions.

### Masks — `VectorMask<E>`

A [`VectorMask<E>`](https://download.java.net/java/early_access/jdk27/docs/api/jdk.incubator.vector/jdk/incubator/vector/VectorMask.html)
is a vector of booleans (one per lane) used to **emulate control flow**: an
operation applies only to lanes whose mask element is `true`. Comparisons
produce masks. On AVX-512 / SVE a mask maps to a **predicate register**; on other
platforms it maps to a vector register plus a blend operation (less efficient).

### Shuffles — `VectorShuffle<E>`

A [`VectorShuffle<E>`](https://download.java.net/java/early_access/jdk27/docs/api/jdk.incubator.vector/jdk/incubator/vector/VectorShuffle.html)
is a vector of `int` lane indexes describing **cross-lane permutation** —
how lane elements move from a source vector to a result vector.

## 5. Canonical example

Scalar version:

```java
void scalarComputation(float[] a, float[] b, float[] c) {
    for (int i = 0; i < a.length; i++) {
        c[i] = (a[i] * a[i] + b[i] * b[i]) * -1.0f;
    }
}
```

Vector version (with a scalar **tail loop** for leftover elements):

```java
static final VectorSpecies<Float> SPECIES = FloatVector.SPECIES_PREFERRED;

void vectorComputation(float[] a, float[] b, float[] c) {
    int i = 0;
    int upperBound = SPECIES.loopBound(a.length);
    for (; i < upperBound; i += SPECIES.length()) {
        var va = FloatVector.fromArray(SPECIES, a, i);
        var vb = FloatVector.fromArray(SPECIES, b, i);
        var vc = va.mul(va)
                   .add(vb.mul(vb))
                   .neg();
        vc.intoArray(c, i);
    }
    for (; i < a.length; i++) { // tail
        c[i] = (a[i] * a[i] + b[i] * b[i]) * -1.0f;
    }
}
```

On AVX-capable x64, HotSpot C2 compiles the hot loop to `vmulps` / `vaddps` /
`vxorps` / `vmovdqu` over `%ymm` registers (256-bit), with all object
allocations elided.

### Masked variant (predicate-register platforms)

With masks you can drop the separate tail loop entirely:

```java
void vectorComputation(float[] a, float[] b, float[] c) {
    for (int i = 0; i < a.length; i += SPECIES.length()) {
        var m  = SPECIES.indexInRange(i, a.length); // suffix of unset lanes on last iter
        var va = FloatVector.fromArray(SPECIES, a, i, m);
        var vb = FloatVector.fromArray(SPECIES, b, i, m);
        var vc = va.mul(va).add(vb.mul(vb)).neg();
        vc.intoArray(c, i, m);
    }
}
```

The mask prevents out-of-bounds access on the final iteration.

> ⚠️ **Caveat:** the masked form is **not always optimal today**. On platforms
> without predicate registers it is generally slower, and even with native mask
> support masked ops can lag unmasked ops. The explicit tail-loop form is the
> safe default across all platforms.

## 6. Run-time compilation

There are **two implementations**:

1. A pure-Java fallback — correct but not optimal.
2. **HotSpot C2 intrinsics** — compile vector operations to hardware vector
   registers/instructions when available.

To avoid an explosion of intrinsics, C2 defines **generalized intrinsics** per
operation kind (unary, binary, conversion, …) parameterized by the operation.

`Vector<E>` and its subclasses are **[value-based classes](https://docs.oracle.com/en/java/javase/26/docs/api/java.base/java/lang/doc-files/ValueBased.html)** —
avoid identity-sensitive operations (`==`, synchronization). C2 treats a vector
value as a single unit (like an `int`/`long`) mapped to a vector register and
specially handles it to overcome escape-analysis limits and avoid boxing. This
will later align with Valhalla value objects.

### Graceful degradation

When a computation can't be fully expressed as efficient vector instructions
(e.g. the CPU lacks an operation), execution **degrades gracefully but stays
correct**. In regular loop cases, fallback can still be competitive with
manually unrolled scalar loops.

## 7. Transcendental & trigonometric math

Floating-point lane-wise transcendental/trigonometric operations are backed by
optimized native libraries with the **same numerical properties as the scalar
`java.lang.Math` equivalents**:

- **x64:** Intel **SVML** (Short Vector Math Library) — Linux & Windows.
- **AArch64 & RISC-V:** **SLEEF** (now **3.9.0**) — Linux & macOS.

Native linking uses Project Panama's **FFM API**. SVML/SLEEF sources ship inside
the `jdk.incubator.vector` module; the build compiles the appropriate one into a
shared library. The SVML library is ~1 MB, but if a `jlink` image **omits**
`jdk.incubator.vector`, the library is not copied in.

---

## 8. `Float16` class

The API includes a value-based
[`Float16`](https://download.java.net/java/early_access/jdk27/docs/api/jdk.incubator.vector/jdk/incubator/vector/Float16.html)
class representing **IEEE 754 binary16** (half-precision) numbers. C2 can
**auto-vectorize** `Float16` addition, subtraction, multiplication, division,
square root, and fused multiply-add on supporting CPUs. It will migrate to a
value class once Valhalla lands.

---

## 9. Platform support

- **Reliable compilation on x64** (SSE/AVX/AVX-512) and **AArch64** (NEON/SVE).
- AVX-512 and SVE additionally provide **predicate registers** for masks.
- Other architectures (e.g. **RISC-V**) are being implemented by contributors
  but are explicit non-goals of this JEP.
- **Not supported:** the C1 compiler; strict (reproducible) floating-point
  semantics for vectors — vector FP results may differ from scalar FP results,
  with deviations documented.

## 10. Using it in this project

`jdk.incubator.vector` is an incubator module, so it must be **added explicitly**
at compile and run time. No `--enable-preview` is required (it is *incubating*,
not *preview*). The compiler emits an incubation warning.

### Maven (`maven-compiler-plugin`)

```xml
<plugin>
  <groupId>org.apache.maven.plugins</groupId>
  <artifactId>maven-compiler-plugin</artifactId>
  <configuration>
    <release>27</release>
    <compilerArgs>
      <arg>--add-modules=jdk.incubator.vector</arg>
    </compilerArgs>
  </configuration>
</plugin>
```

### Running (`java`)

```bash
java --add-modules=jdk.incubator.vector -jar target/rinha-2026-1.0-SNAPSHOT.jar
```

Surefire/tests need the same flag:

```xml
<plugin>
  <groupId>org.apache.maven.plugins</groupId>
  <artifactId>maven-surefire-plugin</artifactId>
  <configuration>
    <argLine>--add-modules=jdk.incubator.vector</argLine>
  </configuration>
</plugin>
```

### Performance tips

- Store the species in a `static final VectorSpecies<E>` field so it is a JIT
  constant.
- Prefer `SPECIES_PREFERRED` for shape portability.
- Use the explicit **tail loop** rather than masks unless you have verified the
  masked form is faster on your target hardware.
- Keep code **shape-invariant**; avoid shape-changing conversions in hot loops.
- Benchmark with **JMH**; warm up enough for C2 to intrinsify the loop.

## 11. Future work & risks

- **Valhalla alignment** — vector classes become value classes; generic
  specialization may make `Vector<E>` over primitive `E` (e.g. `int`) possible,
  potentially removing the need for per-type subclasses like `IntVector`.
- Broaden `Float16` auto-vectorization and add `Float16` *vectors*.
- Improve optimization of loops containing vectorized code.
- Strengthen tests to assert (via C2's IR Test Framework) that vector nodes are
  actually generated.
- Explore synthetic vector shapes for better control of loop unrolling, matrices,
  sorting, and parsing.

**Risk:** the API uses boxed types (e.g. `Integer`) as proxies for primitives
because today's generics are hostile to primitives. When Valhalla introduces
better generics the current design will look awkward and likely change; the JEP
assumes such changes will be possible without excessive backward incompatibility.

## 12. API reference (`jdk.incubator.vector`)

> Module: **`jdk.incubator.vector`** (single package: `jdk.incubator.vector`).
> Signatures below are representative — see the
> [package javadoc](https://download.java.net/java/early_access/jdk27/docs/api/jdk.incubator.vector/jdk/incubator/vector/package-summary.html)
> for the complete list of overloads (most operations have masked/unmasked and
> vector/scalar-broadcast variants).

### 12.1 Type inventory

| Type | Kind | Role |
|------|------|------|
| `Vector<E>` | abstract class | Base vector; element-type-agnostic operations |
| `ByteVector`, `ShortVector`, `IntVector`, `LongVector`, `FloatVector`, `DoubleVector` | abstract classes | Element-type-specific subclasses |
| `VectorSpecies<E>` | interface | Element type + shape; vector factory & reflection |
| `VectorShape` | enum | Vector size in bits |
| `VectorMask<E>` | abstract class | Per-lane booleans (predicate) for conditional ops |
| `VectorShuffle<E>` | abstract class | Per-lane `int` indexes for cross-lane permutation |
| `VectorOperators` | final class | Holder of operator tokens + token interfaces |
| `VectorOperators.Operator` (+ `Unary`, `Binary`, `Ternary`, `Comparison`, `Test`, `Conversion`, `Associative`) | interfaces | Typed operator tokens |
| `Float16` | final value-based class | IEEE 754 binary16 scalar |

### 12.2 `Vector<E>` — common operations

- **Metadata:** `species()`, `elementType()`, `elementSize()`, `shape()`,
  `length()`, `bitSize()`, `byteSize()`.
- **Generic lane-wise:** `lanewise(Unary)`, `lanewise(Binary, Vector)`,
  `lanewise(Ternary, Vector, Vector)` — each with `…, VectorMask` overloads.
- **Named arithmetic/logic:** `add`, `sub`, `mul`, `div`, `neg`, `abs`,
  `min`, `max` (masked + scalar-broadcast overloads).
- **Comparison / tests:** `compare(Comparison, Vector)` → `VectorMask`,
  `eq(Vector)`, `lt(Vector)`, `test(Test)`.
- **Selection / control flow:** `blend(Vector, VectorMask)`,
  `slice`, `unslice`.
- **Cross-lane:** `rearrange(VectorShuffle)`, `rearrange(VectorShuffle, VectorMask)`,
  `selectFrom(Vector)`.
- **Reformatting:** `convert(Conversion, int)`, `convertShape(...)`,
  `castShape(...)`, `reinterpretShape(VectorSpecies, int)`,
  `reinterpretAs{Byte,Short,Int,Long,Float,Double}s()`.
- **Reductions / lanes:** `reduceLanesToLong(Associative)`,
  `toArray()`, `toIntArray()`, `toDoubleArray()`, `lane(int)` (on subclasses).
- **Memory store:** `intoArray(...)`, `intoMemorySegment(...)`,
  `intoBooleanArray(...)` (variants per element type).

### 12.3 Type-specific subclasses (e.g. `FloatVector`)

- **Species constants:** `SPECIES_64`, `SPECIES_128`, `SPECIES_256`,
  `SPECIES_512`, `SPECIES_MAX`, `SPECIES_PREFERRED`.
- **Factories:** `zero(VectorSpecies)`, `broadcast(VectorSpecies, <scalar>)`,
  `fromArray(VectorSpecies, <type>[], int)` (+ masked / indexed-gather overloads),
  `fromMemorySegment(VectorSpecies, MemorySegment, long, ByteOrder)`,
  `fromCharArray` / `fromBooleanArray` where applicable.
- **Unboxed access:** `lane(int)`, `withLane(int, <scalar>)`.
- **Typed reductions:** `reduceLanes(Associative)`,
  `reduceLanes(Associative, VectorMask)`.
- **Element-specific ops:** integral subclasses add bitwise/shift
  (`and`, `or`, `xor`, `lanewise(LSHL/ASHR/…)`); floating-point subclasses add
  transcendentals (`sqrt`, `lanewise(EXP/LOG/SIN/…)`), `fma`.

### 12.4 `VectorSpecies<E>`

`length()`, `elementType()`, `elementSize()`, `vectorShape()`,
`vectorBitSize()`, `loopBound(int)`, `indexInRange(int, int)` → `VectorMask`,
`zero()`, `broadcast(double)`, `fromArray(...)`, `iota()`,
`withLanes(Class)`, `withShape(VectorShape)`; statics `of(Class, VectorShape)`,
`ofLargestShape(Class)`, `ofPreferred(Class)`.

### 12.5 `VectorShape` (enum)

- **Constants:** `S_64_BIT`, `S_128_BIT`, `S_256_BIT`, `S_512_BIT`, `S_Max_BIT`.
- **Methods:** `vectorBitSize()`, `withLanes(Class)`, statics `forBitSize(int)`,
  `forIndexBitSize(int, int)`, `preferredShape()`, `largestShapeFor(Class)`.

### 12.6 `VectorMask<E>`

`length()`, `laneIsSet(int)`, `anyTrue()`, `allTrue()`, `trueCount()`,
`firstTrue()`, `lastTrue()`, `toLong()`, `toArray()`, logical `and`, `or`,
`xor`, `not`, `andNot`, `cast(VectorSpecies)`, `toVector()`;
statics `fromLong`, `fromArray`, `fromValues`.

### 12.7 `VectorShuffle<E>`

`length()`, `toArray()`, `toVector()`, `laneSource(int)`, `wrapIndexes()`,
`checkIndexes()`, `rearrange(VectorShuffle)`, `cast(VectorSpecies)`;
statics `fromArray`, `fromValues`, `iota(...)`, `makeZip` / `makeUnzip`.

### 12.8 `VectorOperators` — operator tokens

Token **interfaces** (each implements `Operator`): `Unary`, `Binary`,
`Ternary`, `Comparison`, `Test`, `Conversion`, `Associative`. Selected
**constants** (static finals on `VectorOperators`):

- **Unary:** `NEG`, `ABS`, `NOT`, `ZOMO`, `BIT_COUNT`, `REVERSE`,
  `REVERSE_BYTES`, `TRAILING_ZEROS_COUNT`, `LEADING_ZEROS_COUNT`,
  `SIN`, `COS`, `TAN`, `ASIN`, `ACOS`, `ATAN`, `EXP`, `LOG`, `LOG10`,
  `SQRT`, `CBRT`, `SINH`, `COSH`, `TANH`, `EXPM1`, `LOG1P`.
- **Binary / Associative:** `ADD`, `SUB`, `MUL`, `DIV`, `MIN`, `MAX`,
  `AND`, `OR`, `XOR`, `AND_NOT`, `LSHL`, `ASHR`, `LSHR`, `ROL`, `ROR`,
  `ATAN2`, `POW`, `HYPOT`, `FIRST_NONZERO`, saturating `SADD`/`SSUB`/`SUADD`/`SUSUB`,
  unsigned `UMIN`/`UMAX`. (Associative subset: `ADD`, `MUL`, `MIN`, `MAX`,
  `AND`, `OR`, `XOR`, `FIRST_NONZERO` — usable with `reduceLanes`.)
- **Comparison:** `EQ`, `NE`, `LT`, `LE`, `GT`, `GE`, unsigned
  `ULT`, `ULE`, `UGT`, `UGE`.
- **Test:** `IS_DEFAULT`, `IS_NEGATIVE`, `IS_FINITE`, `IS_NAN`, `IS_INFINITE`.
- **Ternary:** `FMA`, `BITWISE_BLEND`.
- **Conversion:** numeric casts (`B2I`, `I2D`, `F2L`, `D2I`, …),
  zero-extend (`ZERO_EXTEND_B2I`, …), and bit reinterpret
  (`REINTERPRET_F2I`, `REINTERPRET_D2L`, …).

### 12.9 `Float16` (value-based)

Half-precision (binary16) scalar. Key members: `valueOf(...)`,
`float16ToShortBits` / `shortBitsToFloat16`, `floatValue()`, `doubleValue()`,
`add`, `subtract`, `multiply`, `divide`, `sqrt`, `fma`, plus constants such as
`MAX_VALUE`, `MIN_VALUE`, `NaN`, `POSITIVE_INFINITY`. C2 auto-vectorizes
add/sub/mul/div/sqrt/FMA on supporting CPUs.
